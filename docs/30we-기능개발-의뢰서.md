# 30-we.com 기능 개발 의뢰서

> crawling 프로젝트에서 생산하는 데이터를 30-we.com에서 조회/표시하기 위한 기능 개발 요청 문서.
> 새 기능이 생길 때마다 이 문서에 의뢰 항목을 추가하고, 준비가 되면 한꺼번에 전달한다.
> **의뢰 상세의 코드는 30-we.com의 기존 컨벤션(Bsight 모듈)을 그대로 따라 작성했으므로, 그대로 구현하면 된다.**

---

## 1. 공통 전제 (모든 의뢰에 적용)

### 1.1 두 프로젝트의 역할

| 프로젝트 | 역할 |
|---|---|
| **crawling** (Spring Boot, :8081) | 데이터 생산: 쿠팡 API 연동, 스케줄 수집, 부족 재고 계산, 슬랙 알림, DB 적재 |
| **30-we.com** (Laravel 8, PHP 7.3) | 데이터 소비: crawling이 만든 데이터를 **조회해서 화면에 표시** (읽기 전용) |

- 30-we.com에서는 **쓰기 작업이 없다.** 입고 신청 실행 등 액션성 기능은 전부 crawling 쪽에서 처리한다.
- 30-we.com은 쿠팡 API 키, HMAC 인증, 호출 제한을 전혀 알 필요 없다.
- 테이블은 crawling의 JPA가 자동 생성/관리하므로 **30-we.com에서 마이그레이션을 만들지 않는다.** 모델만 작성한다.

### 1.2 DB 커넥션

crawling이 적재하는 테이블은 AWS RDS의 `bsight` DB에 있다. 30-we.com의 `config/database.php:86-98`에 이미 정의된 `mysql_bsight` 커넥션을 사용한다.

- 모델에 `protected $connection = 'mysql_bsight';`를 명시한다.
- `.env`의 `DB_HOST_BSIGHT` / `DB_DATABASE_BSIGHT`(=bsight) / `DB_USERNAME_BSIGHT` / `DB_PASSWORD_BSIGHT`가 crawling이 쓰는 RDS를 가리키는지 확인 필요. 접속 정보는 이 문서에 적지 않고 별도 전달한다.

### 1.3 데이터 연동 방식 (2가지 패턴)

**패턴 A — DB 직접 조회 (기본):** crawling 스케줄러가 주기 수집해 적재한 테이블을 read-only 모델로 조회. 목록/검색/이력 화면은 전부 이 방식.

**패턴 B — 실시간 내부 API 호출:** "지금 새로고침" 같은 진짜 실시간 값이 필요할 때만, 30-we.com 서버가 crawling의 내부 API를 HTTP 동기 호출한다. crawling이 그 자리에서 쿠팡 API를 호출해 JSON을 즉시 반환하며, 조회 결과는 부수적으로 DB 스냅샷에도 반영된다 (→ 새로고침 후에는 패턴 A의 목록/마지막 동기화 시각도 최신이 됨).

- 인증: 요청 헤더 `X-Internal-Token: {토큰}` (토큰 값은 별도 전달, `.env`에 보관)
- crawling 서버 장애/타임아웃 시 이 호출만 실패 → 화면은 패턴 A의 마지막 동기화 데이터로 폴백

### 1.4 30-we.com에 추가할 공통 설정

`config/services.php`에 추가 (기존 `taskboard_webhook` 항목과 같은 방식):

```php
'crawling' => [
    'base_url' => env('CRAWLING_BASE_URL', 'http://127.0.0.1:8081'),
    'internal_token' => env('CRAWLING_INTERNAL_TOKEN', ''),
],
```

`.env`에 추가 (실제 값은 별도 전달):

```
CRAWLING_BASE_URL=http://{crawling서버주소}:8081
CRAWLING_INTERNAL_TOKEN={별도전달}
```

## 2. 의뢰 목록

| # | 기능 | 연동 방식 | 상태 |
|---|---|---|---|
| 1 | 쿠팡 로켓그로스 재고 현황 조회 화면 | 패턴 A + B | 확정 (crawling 배포 후 전달) |
| 2 | 쿠팡 부족 재고 / 입고 제안 조회 화면 | 패턴 A | 확정 (crawling 배포 후 전달) |
| 3 | 영풍문고 발송 업무 자동화 (부족재고 감지 → 발송수량 입력 → 명세서·송장 자동생성 / 문자는 버튼 발송) | 패턴 A (**예외: 30-we가 액션까지 수행**) | 초안 |
| 4 | 쿠팡 매출(판매) 조회 화면 | 패턴 A | 초안 (스키마 확정, 화면 요구 미정) |

상태 정의: `초안`(스키마 미확정) → `확정`(스키마/코드 확정, crawling 구현 대기) → `전달됨`(작업 시작 가능) → `완료`

> **⚠️ 의뢰 #3은 예외 유형입니다.** 의뢰 #1·#2는 "crawling이 만든 데이터를 30-we가 조회만"(읽기 전용)이지만, **의뢰 #3은 30-we가 이미 보유한 Trade(거래명세서·로젠송장·팝빌문자·재고) 기능을 사용해야 하므로 30-we가 쓰기·액션까지 수행**합니다. 공통 전제(§1)의 "30-we는 읽기 전용" 원칙은 의뢰 #3에 적용되지 않습니다. crawling은 이 건에서 데이터 공급(기존 bsight `sales_record` 적재)만 담당하며 신규 API·전송은 없습니다.

## 3. 의뢰 상세

### 의뢰 #1 — 쿠팡 로켓그로스 재고 현황 조회 화면

**상태: 확정** — 아래 스키마/API는 최종본이며, crawling 배포 완료 시점에 "전달됨"으로 변경 후 작업 시작하면 됨.

#### 1-1. 배경

crawling이 쿠팡 오픈 API로 로켓그로스(로켓창고) 재고를 주기적으로 수집해 `coupang_inventory` 테이블에 최신 스냅샷을 유지한다(vendorItemId 기준 upsert). 이 재고 현황을 조회하는 화면과, 필요 시 실시간 값을 가져오는 새로고침 기능을 만든다.

#### 1-2. 테이블 명세 (참고용 — 생성은 crawling이 함)

```sql
-- ⚠️ 실행하지 마세요. 이 SQL은 컬럼 구조 파악을 위한 참고용 명세입니다.
-- 테이블은 crawling(Spring JPA)이 자동 생성하며, 30-we.com은 조회만 합니다.
CREATE TABLE coupang_inventory (
    inventory_id             BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
    vendor_item_id           BIGINT       NOT NULL,                -- 쿠팡 옵션(SKU) 고유 ID
    external_sku_id          VARCHAR(100) NULL,                    -- 판매자 정의 SKU ID
    product_name             VARCHAR(500) NULL,                    -- 상품명 (상품 API에서 매핑, 매핑 전 NULL 가능)
    orderable_quantity       INT          NOT NULL,                -- 로켓창고 주문 가능 수량
    sales_count_last_30_days INT          NULL,                    -- 최근 30일 판매 수량
    collected_at             DATETIME(6)  NOT NULL,                -- 마지막 동기화 시각
    UNIQUE KEY uk_vendor_item_id (vendor_item_id)
);
```

- 항상 "옵션(SKU)당 1행"인 최신 스냅샷이다. 이력 테이블이 아니다.
- `product_name`은 NULL일 수 있으므로 화면에서 `{{$item->product_name ?? '(상품명 미매핑)'}}` 처리.

#### 1-3. Eloquent 모델 (전체 코드)

`app/Models/CoupangInventory.php` 신규 생성:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class CoupangInventory extends Model
{
    protected $connection = 'mysql_bsight';
    protected $table = 'coupang_inventory';
    protected $primaryKey = 'inventory_id';
    public $timestamps = false; // created_at/updated_at 없음. collected_at만 존재

    protected $casts = [
        'collected_at' => 'datetime',
    ];
}
```

#### 1-4. 라우트 (routes/web.php)

기존 bsight 그룹(`routes/web.php:989` 부근, `['prefix' => 'bsight', 'as' => 'bsight::', 'middleware'=>['admin.access']]`)과 **같은 레벨에** 아래 그룹을 추가:

```php
Route::group(
    ['prefix' => 'coupang', 'as' => 'coupang::', 'middleware' => ['admin.access']],
    function () {
        Route::get('inventory-list', [\App\Http\Controllers\Admin\CoupangController::class, 'inventoryList'])->name('inventoryList');
        Route::get('inventory-realtime', [\App\Http\Controllers\Admin\CoupangController::class, 'inventoryRealtime'])->name('inventoryRealtime');
        Route::get('restock-list', [\App\Http\Controllers\Admin\CoupangController::class, 'restockList'])->name('restockList'); // 의뢰 #2
    }

```

라우트 헬퍼는 기존 관례대로 `route("admin::coupang::inventoryList")` 형태가 된다.

#### 1-5. 컨트롤러 (전체 코드)

`app/Http/Controllers/Admin/CoupangController.php` 신규 생성. BsightController::productList 패턴(권한 체크, 필터, paginate)을 그대로 따름:

```php
<?php

namespace App\Http\Controllers\Admin;

use App\Http\Controllers\Controller;
use App\Models\CoupangInventory;
use App\Models\CoupangRestockSuggestion;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

class CoupangController extends Controller
{
    // [의뢰 #1] 재고 현황 목록 (패턴 A: DB 조회)
    public function inventoryList(Request $request)
    {
        $items = CoupangInventory::whereRaw('1=1');

        if ($request->get('query')) {
            $query = $request->get('query');
            $items = $items->where(function ($q) use ($query) {
                $q->where('product_name', 'like', "%{$query}%")
                  ->orWhere('external_sku_id', 'like', "%{$query}%");
            });
        }

        $item_count = $items->count();
        $last_collected_at = CoupangInventory::max('collected_at'); // 마지막 동기화 시각

        $orderByWhich = $request->get('orderByWhich');
        if ($orderByWhich) {
            $orderByExploded = explode(' ', $orderByWhich);
            $items = $items->orderBy($orderByExploded[0], $orderByExploded[1])->paginate(40);
        } else {
            $items = $items->orderBy('orderable_quantity', 'asc')->paginate(40); // 기본: 재고 적은 순
        }

        if (Auth::user()->hasRole(['system_admin', 'idus_admin'])) {
            $data = [
                'items' => $items,
                'item_count' => $item_count,
                'last_collected_at' => $last_collected_at,
                'realtime' => false,
            ];
            return view('admin.coupang.inventory_list', $data);
        } else {
            echo "<script>alert('권한 없는 페이지입니다.');history.back();</script>";
        }
    }

    // [의뢰 #1] 실시간 재고 조회 (패턴 B: crawling 내부 API 호출)
    public function inventoryRealtime(Request $request)
    {
        if (!Auth::user()->hasRole(['system_admin', 'idus_admin'])) {
            echo "<script>alert('권한 없는 페이지입니다.');history.back();</script>";
            return;
        }

        try {
            $response = Http::withHeaders([
                'X-Internal-Token' => config('services.crawling.internal_token'),
            ])->timeout(15)->get(config('services.crawling.base_url') . '/internal/coupang/inventory');

            if (!$response->successful()) {
                Log::error('crawling 실시간 재고 API 오류', [
                    'status' => $response->status(),
                    'body' => $response->body(),
                ]);
                return redirect()->route('admin::coupang::inventoryList')
                    ->with('error', '실시간 조회에 실패했습니다. 마지막 동기화 데이터를 표시합니다.');
            }

            $result = $response->json();
            // 실시간 결과는 페이징 없이 전체 표시 (SKU 수십~수백 개 수준)
            $data = [
                'items' => collect($result['items']),
                'item_count' => count($result['items']),
                'last_collected_at' => $result['collectedAt'],
                'realtime' => true,
            ];
            return view('admin.coupang.inventory_list', $data);
        } catch (\Exception $e) {
            Log::error('crawling 실시간 재고 API 연결 실패', ['message' => $e->getMessage()]);
            return redirect()->route('admin::coupang::inventoryList')
                ->with('error', '실시간 조회에 실패했습니다. 마지막 동기화 데이터를 표시합니다.');
        }
    }

    // [의뢰 #2] 부족 재고 / 입고 제안 목록 — 의뢰 #2 참고
    public function restockList(Request $request)
    {
        // 의뢰 #2의 코드 참고
    }
}
```

주의: `$items`가 실시간 모드에서는 Collection, DB 모드에서는 Paginator이므로 blade에서 `$realtime` 플래그로 분기한다 (아래 뷰 명세 참고). PHP 7.3 환경이므로 arrow function(`fn()`)·nullsafe(`?->`) 사용 금지 — 위 코드는 모두 7.3 호환.

#### 1-6. crawling 내부 API 명세 (패턴 B, crawling이 제공)

```
GET {CRAWLING_BASE_URL}/internal/coupang/inventory
Header: X-Internal-Token: {토큰}
```

성공 응답 `200`:

```json
{
  "collectedAt": "2026-08-21T14:30:00",
  "items": [
    {
      "vendorItemId": 70000000000,
      "externalSkuId": "10012345",
      "productName": "상품명 (미매핑이면 null)",
      "orderableQuantity": 10,
      "salesCountLast30Days": 15
    }
  ]
}
```

오류 응답:

| status | body | 30-we.com 처리 |
|---|---|---|
| 401 | `{"error": "unauthorized"}` | 토큰 설정 확인 필요. 목록으로 리다이렉트 + 오류 메시지 |
| 502 | `{"error": "coupang_api_error", "message": "..."}` | 쿠팡 쪽 오류. 목록으로 리다이렉트 + 오류 메시지 |
| (연결 실패/타임아웃) | - | 목록으로 리다이렉트 + 오류 메시지 (컨트롤러 catch 블록) |

- crawling 내부에 1분 TTL 캐시가 있으므로 연타해도 안전하다. 30-we.com에서 별도 스로틀링 불필요.
- 실시간 조회 결과는 crawling이 `coupang_inventory` 스냅샷에도 반영하므로, 새로고침 직후에는 목록 화면(패턴 A)의 데이터와 마지막 동기화 시각도 함께 최신화된다.

#### 1-7. 뷰

`resources/views/admin/coupang/inventory_list.blade.php` 신규 생성. **`resources/views/admin/bsight/product_list.blade.php`를 복사해서 수정하는 것을 권장** (같은 레이아웃 `layouts.uknowad`, 같은 breadcrumb/card/페이징 구조).

화면 구성:

1. breadcrumb: `쿠팡 로켓그로스 > 재고 현황 :: {{number_format($item_count)}} 개`
2. 상단 우측: 마지막 동기화 시각 + 새로고침 버튼
   ```php
   @if ($realtime)
       <span class="badge badge-success">실시간 조회 결과</span>
   @else
       <span>마지막 동기화: {{$last_collected_at}}</span>
   @endif
   <a type="button" class="btn btn-warning" href="{{route('admin::coupang::inventoryRealtime')}}">지금 새로고침</a>
   ```
3. 오류 플래시 표시:
   ```php
   @if (session('error'))
       <div class="alert alert-danger">{{session('error')}}</div>
   @endif
   ```
4. 검색 폼 (GET, 패턴 A에서만): 검색어 `query`(상품명/SKU ID), 정렬 `orderByWhich` — 옵션: `orderable_quantity asc`(재고 적은 순, 기본), `orderable_quantity desc`, `sales_count_last_30_days desc`(판매 많은 순)
5. 테이블 컬럼:

   | 헤더 | 값 (DB 모드) | 값 (실시간 모드) |
   |---|---|---|
   | 상품명 | `{{$item->product_name ?? '(미매핑)'}}` | `{{$item['productName'] ?? '(미매핑)'}}` |
   | SKU ID | `{{$item->external_sku_id}}` | `{{$item['externalSkuId']}}` |
   | 옵션 ID | `{{$item->vendor_item_id}}` | `{{$item['vendorItemId']}}` |
   | 주문가능수량 | `{{number_format($item->orderable_quantity)}} 개` | `{{number_format($item['orderableQuantity'])}} 개` |
   | 최근 30일 판매 | `{{number_format($item->sales_count_last_30_days)}} 개` | `{{number_format($item['salesCountLast30Days'])}} 개` |

   구현 단순화를 위해 blade 상단에서 실시간 모드일 때 배열을 객체 형태로 변환해도 됨:
   ```php
   @php
       if ($realtime) {
           $items = $items->map(function ($row) {
               return (object) [
                   'product_name' => isset($row['productName']) ? $row['productName'] : null,
                   'external_sku_id' => isset($row['externalSkuId']) ? $row['externalSkuId'] : null,
                   'vendor_item_id' => $row['vendorItemId'],
                   'orderable_quantity' => $row['orderableQuantity'],
                   'sales_count_last_30_days' => isset($row['salesCountLast30Days']) ? $row['salesCountLast30Days'] : 0,
               ];
           });
       }
   @endphp
   ```
6. 페이징 (패턴 A에서만):
   ```php
   @if (!$realtime)
       {{$items->appends(request()->except('page'))->render()}}
   @endif
   ```

### 의뢰 #3 — 영풍문고 발송 업무 자동화

**상태: 초안** — 착수 전 아래 "3-0. 선행 실측"을 먼저 수행해 상품 매칭율을 확인한 뒤 진행. 매칭율이 낮으면 담당자와 협의.

> **이 의뢰는 예외입니다.** 30-we가 이미 보유한 Trade 모듈(거래명세서·로젠 송장·팝빌 문자·재고 로그)을 사용하므로 **읽기 전용이 아니라 쓰기·액션까지 30-we가 수행**합니다. crawling은 기존대로 영풍 판매를 `bsight.sales_record`에 적재만 하며(이미 운영 중), 이 건에 신규 API·전송은 없습니다.

#### 3-0. 배경 및 업무 흐름

영풍문고 발송 담당자의 수작업(① 영풍 SCM에서 판매내역 확인 → ② 지점별 엑셀에 판매수량 수기 입력·잔여재고 계산 → ③ 거래명세서·발송내역서·송장 작성 → ④ 발송 → ⑤ 지점 안내 문자)을 자동화한다. ①②는 이미 crawling이 매일 `sales_record`에 수집하므로, 30-we는 **그 데이터를 읽어 "부족재고 감지 → 관리자 발송수량 입력 → 문서 자동생성"** 을 담당한다.

**전체 흐름 (매일 + 발송 시점):**
```
[매일 06:00] trade:detectLowStock (신규 커맨드)
   위탁거래처(영풍 지점) × 상품별  현재고 = 재고로그 합산 − bsight 판매량
   → 현재고 <= 설정임계치(stock_alert_qty) 이면 부족재고
   → Slack 알림 (지점·상품·현재고·임계치) + 바코드 미매칭 경고

[관리자] 재고관리 화면 "발송 준비" 패널에서 지점×상품 발송수량 입력 → 생성 버튼
   → createShipment (신규): 거래명세서(위탁) 생성 → 발송내역서 PDF
   → 다음 단계: 미리 등록한 지점 정보(주소·연락처) 기반 로젠 송장 발급
   → (물리작업: 패킹·송장부착·발송)
   → 관리자 "로젠 출력 확인" → 재고 자동 차감 (기존 흐름)
   → 관리자가 "문자 발송하기" 버튼 클릭 → 해당 지점에 템플릿 기반 문자 전송 (자동 아님)
```

**핵심 전제 — 상품 매칭:** bsight `product.product_code`(영풍 바코드) 와 30-we `TradeProduct` 바코드(`barcode_list`)를 **완전일치(=)** 로 매칭한다. 매칭 안 된 상품은 판매 집계에서 빠져 재고가 실제보다 많게 보이므로(→ 부족감지 누락, 발주 사고), 반드시 경고를 노출한다.

**crawling 측 데이터 실측 결과(2026-08, 참고):** 영풍 판매 상품 102종 전부 13자리 순수숫자(EAN-13), 공백·특수문자 없음. bsight product 전체 214종 중 213종이 정상 13자리(1종은 빈 코드 유령 레코드). 즉 바코드 품질은 양호하며, 매칭 실패가 있다면 대부분 "30-we `TradeProduct`에 해당 바코드가 미등록"인 경우다.

#### 3-0-2. 바코드 정규화 정합성 (양쪽 동일 규칙 — 30-we도 적용)

매칭은 `bsight.product_code == TradeProduct 바코드` **완전일치**이므로, 한쪽에만 공백/특수문자가 섞이면 조용히 매칭 실패한다(silent failure). **양쪽이 동일한 정규화 규칙**을 적용해야 안전하다.

- **규칙(양쪽 공통):** 앞뒤·내부의 모든 공백류(스페이스/탭/개행/NBSP) 제거, 결과가 빈 문자열이면 저장하지 않음. **"숫자만 남기기" 같은 공격적 변형은 금지**(ISBN 부가기호·비도서 코드 손상 위험).
- **crawling 측(이미 완료):** 저장 시 정규화 적용 완료(`BarcodeNormalizer`). 기존 bsight 214종 전수 검증 결과 **정규화해도 값이 바뀌는 것 0건**(이미 깨끗). 즉 정규화로 기존 데이터가 다른 값이 되어 중복 생성될 위험 없음.
- **30-we 측(이 의뢰에 포함):**
  1. **신규 등록 정규화** — `TradeProduct` 바코드(및 `TradeProductBarcode`) **등록/수정 저장 시** 위 규칙으로 정규화. `postProduct`/바코드 저장 지점에 `preg_replace('/[\s\x{00A0}]/u', '', trim($barcode))` 적용(PHP 7.3 호환) 후, 빈값이면 저장 스킵.
  2. **기존 데이터 소급 정리(1회)** — `trade_products.barcode` + `trade_product_barcodes.barcode`의 기존 값 중 정규화하면 달라지는 것이 있는지 먼저 조회하고(읽기 전용), 있으면 1회 UPDATE로 정리. **수기 입력이라 crawling보다 공백 위험이 높으므로 반드시 확인.** 소급 UPDATE 전 백업 권장.

> 주의: 신규만 정규화하고 기존을 두면, 기존에 공백 든 바코드는 계속 매칭 실패한다. 그래서 소급 정리가 필요하다.

#### 3-0-1. 선행 실측 (착수 전, 읽기 전용 — 30-we 환경에서 수행)

**재고·판매 계산 로직은 기존 `TradeController::getInventory`(`TradeController.php:5112-5267`)에 이미 완성**돼 있다. 커맨드가 이를 재사용하도록, 아래 private 메서드들을 **`app/Services/TradeInventoryService.php`(신규)로 추출**하고 컨트롤러는 위임하게 한다(화면 동작 보존을 위해 getInventory의 반환 배열 `stock/stockAlerts/bsightSales` 형태는 절대 변경 금지 — `resources/views/admin/trade/inventory.blade.php`가 의존).

추출 대상(현재 TradeController의 private, 전체 코드 그대로 이동):
- `calculateStockByPlace($userId)` (4730-4761): 재고로그(`TradeInventoryLog`)를 `to`(+)/`from`(−) 방향으로 GROUP BY 합산 → `['partner_{id}'=>['product_id'=>qty], 'location_{id}'=>..., 'shipment_{id}'=>...]`.

- **bsight 판매 차감 블록** (getInventory 5158-5233): 아래 SQL이 핵심.

```php
// bsight 실시간 판매량 (getInventory 5202-5217 원본) — mysql_bsight 커넥션, 읽기 전용
$salesRecords = DB::connection('mysql_bsight')
    ->table('sales_record')
    ->join('product', 'sales_record.product_id', '=', 'product.product_id')
    ->where(function ($query) use ($locationFromDates, $today) {
        foreach ($locationFromDates as $locationId => $fromDate) {
            $query->orWhere(function ($q) use ($locationId, $fromDate, $today) {
                $q->where('sales_record.location_id', $locationId)
                  ->whereBetween('sales_record.sales_date', [$fromDate, $today]);
            });
        }
    })
    ->whereIn('product.product_code', array_values($productBarcodes))  // TradeProduct 바코드들
    ->select('sales_record.location_id', 'product.product_code',
             DB::raw('SUM(sales_record.quantity) as total_qty'))
    ->groupBy('sales_record.location_id', 'product.product_code')
    ->get();
// $locationFromDates: 거래처별 조회 시작일 = 최신 정산명세서(supply_type=settlement, invoice_issued_at) supply_date, 없으면 한 달 전 (getInventory 5179-5200)
// product_code → product_id 매핑: TradeProduct.barcode_list 로 barcodeToProductId 맵 구성 (5164-5173)
// 차감: $stock['partner_'.$partner->id][$productId] -= total_qty
```

**커맨드 골격 (전체 코드):**

```php
<?php

namespace App\Console\Commands;

use App\Models\TradePartner;
use App\Models\TradePartnerProduct;
use App\Models\TradeProduct;
use App\Services\TradeInventoryService;
use Illuminate\Console\Command;

class DetectLowStockTrade extends Command
{
    protected $signature = 'trade:detectLowStock {--user=} {--dry-run}';
    protected $description = '위탁 거래처(영풍 등) 부족재고 감지 및 Slack 알림';

    // ALLOWED_USER_IDS = [1, 19603] (TradeController와 동일)
    private $targetUserIds = [1, 19603];

    public function handle(TradeInventoryService $inventory)
    {
        $userOpt = $this->option('user');
        $userIds = $userOpt ? [(int) $userOpt] : $this->targetUserIds;
        $dryRun = (bool) $this->option('dry-run');

        foreach ($userIds as $userId) {
            $result = $inventory->detectShortages($userId);   // [{partner, product, current, alertQty}], + unmatched
            $shortages = $result['shortages'];
            $unmatched = $result['unmatched'];

            if (empty($shortages) && empty($unmatched)) {
                $this->info("user {$userId}: 부족재고 없음");
                continue;
            }

            $msg = $this->buildMessage($userId, $shortages, $unmatched);
            $this->info($msg);
            if (!$dryRun) {
                $this->sendSlack($msg);
            }
        }
        return 0;
    }

    private function buildMessage($userId, array $shortages, array $unmatched)
    {
        $lines = ["# 부족재고 알림 (user {$userId})"];
        foreach ($shortages as $s) {
            $lines[] = "· {$s['partner_name']} / {$s['product_name']}: 현재 {$s['current']}개 (임계 {$s['alert_qty']})";
        }
        if (!empty($unmatched)) {
            $lines[] = "\n⚠️ 바코드 미매칭 " . count($unmatched) . "건 (집계 누락 가능): "
                     . implode(', ', array_slice($unmatched, 0, 20));
        }
        return implode("\n", $lines);
    }

    // BsightLibrarySalesReport::send_slack(37-79) 패턴. 단 웹훅은 config로.
    private function sendSlack($message)
    {
        $url = config('trade.slack_webhook');   // config/trade.php: env('TRADE_SLACK_WEBHOOK')
        if (!$url) return;
        $payload = ['blocks' => [['type' => 'section', 'text' => ['type' => 'mrkdwn', 'text' => $message]]]];
        $ch = curl_init();
        curl_setopt_array($ch, [
            CURLOPT_URL => $url, CURLOPT_RETURNTRANSFER => true, CURLOPT_TIMEOUT => 30,
            CURLOPT_CUSTOMREQUEST => 'POST', CURLOPT_POSTFIELDS => json_encode($payload),
            CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
        ]);
        curl_exec($ch);
        curl_close($ch);
    }
}
```

`TradeInventoryService::detectShortages($userId)` 가 할 일 (getInventory 로직 재사용):
1. 위탁 거래처: `TradePartner::forUser($userId)->active()->where('trade_type', TradePartner::TRADE_TYPE_CONSIGNMENT)->get()` (bsight_location_id 있는 것만).
2. 활성 제품: `TradeProduct::forUser($userId)->active()->with('barcodes')->get()` → `barcode_list`로 `barcodeToProductId` 맵.
3. `calculateStockByPlace` + `appendInTransitStock` + bsight 판매차감(위 SQL) → 거래처별 현재고.
4. 임계치: `TradePartnerProduct::forUser($userId)->whereNotNull('stock_alert_qty')->whereIn('partner_id', 위탁거래처ids)->get()`.
5. `현재고 <= stock_alert_qty` 인 (거래처, 상품, 현재고, 임계치) 목록 = `shortages`.
6. bsight에서 팔렸는데 `barcodeToProductId`에 없는 product_code = `unmatched`(미매칭 경고).

**(1) `postSupply` 트랜잭션 본문을 Service로 추출**

`app/Services/SupplyService.php`(신규)에 `createSupply(User $user, array $data): TradeSupply`를 만든다. **본문은 `postSupply`(2524-2728)의 `DB::transaction` 내부(2538-2717)를 그대로 옮기되**, `$request->get('x')` → `$data['x']`(널 병합)로 치환하고 `$user`는 인자로 받는다. `postSupply`는 이 Service를 호출하도록 위임해 **기존 화면 동작을 보존**한다.

```php
public function createShipment(Request $request)
{
    $user = $this->checkAccess();

    $partnerId = $request->get('partner_id');

    $validItems = [];

    $message = '';

            'supply_date'           => $request->get('supply_date', now()->toDateString()),
            'delivery_date'         => $request->get('delivery_date'),

        // 2) 로젠 송장 발급 (logenPrintForSupplies 재사용) — 재고 차감은 여기서 하지 않음(출력확인 시점)
        $logen = $this->logenPrintForSupplies($user->id, [$supply->id]);

        $isSuccess = false;
        $message = $e->getMessage();

    return response()->json([
        'isSuccess'   => $isSuccess,
        'message'     => $message,
```

#### 3-5. 지점(거래처) 정보 등록 — 기존 기능 재사용, 신규 UI 없음

송장·문자에 필요한 **지점별 주소·연락처는 기존 "거래처 등록" 기능에 이미 있다.** 별도 화면을 새로 만들지 말 것.

- 영풍 각 지점을 **위탁 거래처(`TradePartner`, `trade_type=consignment`)로 1개씩 등록**한다. 기존 `TradeController::postPartner`(226-275)가 아래를 모두 받는다:
  - `name`(지점명), `contact_number`(문자 수신번호), `address`(송장 주소), `bsight_location_id`(영풍 `sales_location.id`와 연결 — 판매 집계 매칭 키), `business_number`/`owner`/`email` 등.
- 명세서 생성 시 이 거래처 정보가 수취인으로 자동 반영된다(`TradeSupply.resolved_receiver_*` — 명세서에서 별도 입력하면 그 값 우선, 없으면 거래처 기본값). 즉 **송장의 주소·수취인은 거래처에 등록해두면 자동**이다.
- 따라서 "지점별 주소 입력하는 곳"은 **기존 거래처 등록/수정 화면** 그대로다. 운영에서 영풍 36개 지점을 위탁 거래처로 등록하고 `bsight_location_id`를 매핑하면 된다.

> ⚠️ `bsight_location_id` 매핑이 빠지면 그 지점 판매가 재고에서 차감되지 않는다(부족감지 누락). 지점 등록 시 필수.

#### 3-5-1. 초기 재고 입력 (운영 준비 — 코드 아님)

각 위탁 거래처(영풍 지점)×상품의 현재 실재고를 기존 재고 조정 기능(`TradeController::inventoryAdjust`, `TradeInventoryLog` type='adjust')으로 1회 입력해야 감지가 정확해진다. 신규 기능 불필요, 운영 작업.

#### 3-7. 제약 / 주의

### 의뢰 #4 — 쿠팡 매출(판매) 조회 화면

**상태: 초안** — 테이블 스키마는 확정(crawling 수집 가동 중). 화면 요구사항이 정해지면 컨트롤러/뷰 코드를 채워 "확정"으로 올림.

#### 4-1. 배경

crawling이 쿠팡 로켓그로스 주문을 매일 수집해 "결제일 × 옵션(SKU)" 단위 판매 집계를 `coupang_sales`에 적재한다 (매일 05:30, 최근 3일 창 재수집으로 지연 주문 보정). 서점 `sales_record`의 쿠팡 버전이며, 향후 쿠팡 매출 리포트 화면의 데이터 소스가 된다.

#### 4-2. 테이블 명세 (참고용 — 생성은 crawling이 함)

```sql
-- ⚠️ 실행하지 마세요. 이 SQL은 컬럼 구조 파악을 위한 참고용 명세입니다.
-- 테이블은 crawling(Spring JPA)이 자동 생성하며, 30-we.com은 조회만 합니다.
CREATE TABLE coupang_sales (
    sales_id        BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
    sales_date      DATE         NOT NULL,        -- 결제일 (한국시간)
    vendor_item_id  BIGINT       NOT NULL,        -- 쿠팡 옵션(SKU) 고유 ID
    product_name    VARCHAR(500) NULL,            -- 상품명 (미매핑 시 NULL)
    quantity        INT          NOT NULL,        -- 그날 판매 수량 합계
    sales_amount    BIGINT       NOT NULL,        -- 그날 매출액 합계 (수량 × 단가)
    collected_at    DATETIME(6)  NOT NULL,        -- 수집 시각
    UNIQUE KEY uk_sales_date_item (sales_date, vendor_item_id)
);
```

- 취소/환불 차감은 반영되지 않음 (쿠팡 주문 API가 결제 완료 기준). 정산 수준의 정확도가 필요하면 별도 논의.

#### 4-3. Eloquent 모델 (전체 코드)

`app/Models/CoupangSales.php` 신규 생성:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class CoupangSales extends Model
{
    protected $connection = 'mysql_bsight';
    protected $table = 'coupang_sales';
    protected $primaryKey = 'sales_id';
    public $timestamps = false;

    protected $casts = [
        'sales_date' => 'date',
        'collected_at' => 'datetime',
    ];
}
```

#### 4-4. 화면 요구 (미정 — 확정 시 코드 첨부)

예상 후보: 기간별 매출 합계, 일별 추이, 상품별 판매 순위. 기존 매출 조회 화면 패턴(paginate + 기간 필터) 재사용 예정.
